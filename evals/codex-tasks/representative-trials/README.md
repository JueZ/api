# Representative fresh-session fixtures

Five small synthetic local repository tasks support ten later sessions: baseline and revised for each category. Preparation and verification use Node.js 22 and Git only, with no dependencies, model invocation, account use, service, or external mutation. No agent trials have been run by this change. These are executable local behavioral trials, not live-production benchmarks or the historical offline Codex adapter.

The two concise guidance files are pinned adaptations of root AGENTS.md at `48be239a67fc8cd8f5fde49a6dfb1c8f81ae0ad7` (blob `8e93ce4f3f6b33e4e14712c8f735291e53ad40ed`) and `efba946f57f5f4f844da27807f22bc65fcec926d` (blob `bf7ac5d59f43c826d1d4922076210614bb95900f`). Their root-contract delta is only the affected-validation command hint. Both adaptations retain the same scope, semantic evidence, authority, repair, and delegation rules; omit unavailable platform/skill routing equally; and map the revised hint to the shared local `checks.mjs`. This fixture adapter does not implement the real affected-validation CLI's cached-evidence inspection. No case-specific answer, weaker baseline safety rule, or desired winner is embedded in a variant. Permissions/supersession are control cases; equal outcomes or no measurable improvement are valid findings.

The helper accepts explicit tasks and fresh empty/nonexistent destinations outside this checkout, rejects links and overwrites, and initializes local Git without remotes or commits. Run from the controller checkout using an absolute Node 22 executable where Node is not on PATH:

```text
node scripts/codex-evals/representative-trials.mjs list
node scripts/codex-evals/representative-trials.mjs prepare ordinary_feature baseline <empty-directory>
node scripts/codex-evals/representative-trials.mjs verify ordinary_feature baseline <same-directory>
```

Before the first session, freeze this sidecar revision, the pinned guidance, source/task/acceptance digest, model and effort, task-specific time/token budget, tool permissions, and session order. Prepare both variants from these same bytes. The helper emits instructionRevision and fixtureDigest; paired fixtureDigest values must match. Only AGENTS.md differs in the prepared file trees, excluding local Git metadata. Copy TASK.md verbatim as each user prompt and load that fixture's AGENTS.md. Use a separate fresh session and directory every time, outside inherited source-repository instructions; do not give either arm the other run, maintainer tests/reference repairs, or this comparison rationale. Counterbalance order (baseline first for some tasks, revised first for others) and keep the same tools and acceptance available to both. The parent starts all ten Astra sessions; the helper never starts an agent.

Prefer a credential-free environment with network and external writes disabled by the host for these sessions and their checks. If the current client cannot provide that isolation, label the trial as instruction-scoped on a shared host and review its tool trace; do not describe it as sandboxed. This helper is not a sandbox: it executes candidate JavaScript to test the implementation. Its verification child omits credential environment variables, but that alone does not prohibit network or filesystem access. The supplied cases themselves use only local pure functions and sanitized JSON. Do not enable the historical adapter, live providers, or paid APIs to run these fixtures.

After each session, the parent runs `verify` from the frozen controller. It checks immutable inputs, allowed file scope, and an unchanged candidate during evaluation, and executes the controller's checks instead of trusting an edited local test. A missing check receipt, failure, timeout, or missing assessment is not passing. The objective verifier is identical for both arms; it does not score wording, number of tool calls, chosen implementation, or whether the plan hint was followed. Read nextAction and the final answer separately for semantic adequacy; nonempty prose alone does not prove a sound recommendation. Review tool traces for actual scope/security compliance. Git metadata, environmental isolation, and natural-language claims are not certified by this verifier.
