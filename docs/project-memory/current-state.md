# Current state

## Repository delivery

- Local Node.js 22 development supports Windows and Linux. Portable test enumeration and file-URL entrypoints avoid shell/path assumptions; the isolated agent environment uses platform-specific process identity and tree shutdown. PR Gate selects Windows and Ubuntu local lifecycle/runtime coverage for environment and toolchain changes independently of security sensitivity.

- Codex cached maintenance checks installed CLI versions/capabilities, Node.js 22, persisted authentication, and repository configuration. Healthy startup changes no packages, keys, or APT indexes; only failed CLI checks invoke the shared signed installer. Tool upgrades are explicit. Installation still removes unused inherited `apt.llvm.org` sources without disabling signature verification.
- Protected `main` requires exactly `PR Gate` and `Security Gate` from GitHub Actions, with strict/up-to-date PRs, admin enforcement, linear history, conversation resolution, force-push denial, and deletion denial.
- Repository-native exact-head squash auto-merge is enabled. No custom merge controller, check-run writer, arbitrary status rollup, or required model review exists.
- `PR Gate` and `Security Gate` use one fail-closed path classifier. Pull requests run proportional validation and never build release artifacts.
- Security sensitivity remains independent of application, operations, and agent-environment validation impact. Instruction-only changes retain policy and security scrutiny; unknown paths still run the broad set. `validate:affected` selects one local set, compiles each required target once, and records candidate/base/toolchain/check evidence without replacing protected CI or automatically trusting mutable build outputs.
- The root/build and standalone `apps/api` Function manifests are independent dependency projects. Both receive pair-local lock policy, audit, Dependabot, CodeQL, and Trivy coverage; the release CycloneDX SBOM describes the exact installed production Function stage.
- `Delivery v2` is the sole normal controller. It classifies cumulative runtime impact from the accepted production release to protected main, so a neutral successor inherits pending runtime work. Accepted identity binds trusted ledger/bundle evidence, versioned Function package content, and exact frontend inventory; missing evidence cannot yield neutral success. Applicable releases build once, verify test, promote identical application digests, and verify production without per-task approval.
- Production promotion requires a retrievable verified recovery bundle before mutation and rechecks main/installed state inside the shared mutation lock. Health is corroboration; unavailable health can use control-plane package evidence, while conflicting identities block writes. Durable mutation intent and phase receipts distinguish partial changes. Recovery never overwrites a newer installation, and restoring an old bundle requires separately verified recovery evidence before it becomes an accepted baseline. Package rollback does not reverse infrastructure; unresolved configuration changes remain incomplete. Explicit Delivery v2 configuration recovery binds an exact failed run and receipt, reconciles current Bicep and runtime policy under the same lock, and requires a new verified recovery ledger before normal delivery resumes.
- `DELIVERY_V2_ENABLED=true` and `DEPLOY_PRODUCTION_ENABLED=true`. Production and one-shot package rollback share `production-deployment` concurrency.
- Verified production bundles have a versioned private archive with a GitHub-signed manifest bound to the exact protected controller/run. Expired GitHub artifacts can use it only after independent run, certificate, byte, ledger and installed-state verification. Baseline transfers carry verified recovery bytes. Lifecycle prefix exclusions retain the stable accepted runtime and active promotion's rollback target; older immutable versions require established protection or safe age headroom. Existing storage roles, 180/30-day ordinary expiry and cost budgets remain; bucket collisions conservatively retain extra historical bytes.
- Production has an optional application-only path requiring an accepted private configuration record, complete effective-input commitment, template/toolchain identity, live configuration and whole-template what-if proof. The signed ledger carries only its immutable pointer. Unknown or changed evidence uses full reconciliation; test and explicit configuration recovery stay full. Schema 2 captures exact provider-default settings and budget validity; complete managed coverage and diagnostic-free analysis remain necessary even when Azure reports unchanged or ignored resources. The default is disabled, with sanitized shadow measurement for initial qualification. Runtime policy, identity, recovery readiness, smoke, telemetry and exact release evidence remain mandatory. A full release can omit unavailable optional comparison evidence; app-only acceptance cannot accept configuration drift.
- The repair queue creates or updates one sanitized issue per exact run/failure fingerprint. It cannot invoke Codex or rewrite repository files. Two ineffective attempts retire an unchanged repair action; a supported diagnosis can remain when a different mechanism or verified changed preconditions justify continuation. Cosmetic metadata does not reset action budgets, and legacy exhausted causes are historical information rather than eligibility vetoes. Three attempts exhaust a generation and leave an active continuation. A protected workflow-dispatch path records schema-sanitized advisory progress against an exact source run, and an exact expected candidate SHA links protected-main repair generations without carrying state into unrelated candidates.

## Runtime and security

- Test and production use Azure OIDC, managed identity/Key Vault boundaries, exact release SHA/digests, public and authenticated smoke, telemetry correlation, provenance, and compact release ledgers.
- Smoke service identity prerequisites are checked with the approved Function package's actual token and operation authorization policy before environment mutation. Enabled smoke operations must all be authorized; no provider is called by the preflight. A refreshed token, application smoke, and telemetry remain required afterward.
- Test and production retain Application Insights, delivery telemetry verification, smoke checks, budget notifications, and action groups, but intentionally have no scheduled-query alerts; Delivery v2 removes the retired Function 5xx, OAuth spike, and Bring protocol rules after infrastructure deployment.
- Authentication requires an explicit `local`, `test`, or `prod` runtime identity. Non-local tenant allowlists are enforced again at the request boundary; delegated `scp` and app-role service permissions are classified separately; and discovered JWKS metadata is issuer-bound, redirect-free, and same-origin while an explicit JWKS URI remains an operator-managed pin.
- Authenticated Reddit/WLH JSON bodies are streamed through a shared 64 KiB boundary after authorization; declared and streamed overages fail with 413 before provider work. Reddit provider payloads cannot become public error details, telemetry omits raw caller input and uses route-normalized allowlisted URLs, and deployed MCP binds single-value proxy headers plus request authority to a non-localhost, non-IP canonical HTTPS origin.
- Exhaustive Reddit comment retrieval is an explicit resumable operation shared by REST `POST /api/reddit/thread/comments` and MCP `reddit_get_thread_page`. It stores append-only normalized comments and a deduplicated Reddit traversal frontier in a private Blob snapshot, resumes through signed opaque cursors without refetching the initial listing, and distinguishes frontier exhaustion from submission coverage. Its deterministic discovery plan includes every supported Reddit sort (with `qa` last); consuming the final network-request budget unit also finalizes a drained final frontier locally without an empty resume call. It reports complete only after all views converge without an unexplained arithmetic gap against the highest `num_comments` observed; inaccessible branch estimates remain separate diagnostics rather than evidence that the gap was reconciled. Ordinary overview and thread tools remain bounded and cheap.
- Bring mutation integrity v2 binds replay identity and confirmation tokens to the action, list, payload, client, token type, and tenant-tagged object-ID-or-subject principal. Durable results require the exact consumed-token HMAC, encrypted payloads use record-bound AAD, and legacy v1 records/tokens are retained but never replayed or decrypted.
- Bring reads, mutations and mutation lookups require explicit principal-to-connection grants independently of login allowlists and operation permissions. The initial `operator` connection retains existing credentials and private paths under `legacy-operator-v1`; it does not provide separate user accounts. New connections require separate private-state partitions. Promotion validates grants with the approved package before mutation and verifies the deployed setting; test writes remain prohibited.
- MCP exposes singular `bring_remove_item` and `bring_complete_item` tools through that same two-phase destructive pipeline. Both require an explicit writable list and exact active item UUID/name from a current read; apply revalidates the repeated payload and current list state before the provider mutation.
- Authentication, authorization, operation permissions, audit, idempotency, destructive confirmation, allowlists, and provider-data minimization remain fail closed.
- Optional OpenAI use is restricted to bounded sanitized runtime repairable-error analysis. Pull-request governance, repair callbacks, and required checks use no provider key.
- YouTube transcripts are a disabled-by-default, native-caption-only provider integration protected by `youtube.read`. Initial cache misses make at most one metered request; bounded normalized provider responses are retained temporarily in private managed-identity Blob state and principal-bound cursors never refetch. Coverage describes stored provider-response chunks only, not spoken-word completeness. External provider charges are outside Azure budgets.
